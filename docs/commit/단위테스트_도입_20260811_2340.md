# 단위테스트_도입 — Implementation Result

## 요약

`platform` 10개 영역(collision/engine/entity_component/geometry/logging/math/model_import/persistence/serialization/Win32Window) 전체에 대해 Google Test 기반 단위 테스트 빌드 인프라를 처음 도입하고, 각 영역의 클래스에 단위 테스트를 작성했다. `World-of-Tank-imitation-Refactoring/tests/`에 이미 검증되어 있던 37개 테스트 파일을 이식하고, 부족한 부분(`Vec2`, `TinyObjWrapper`, `UfbxWrapper`, `CgltfWrapper`, platform 전용 `SaveLoadManager` 더블, `SaveAsync` 커버리지)을 새로 작성해 총 247개 테스트 케이스로 구성했다. platform 단독 빌드(VS 2022, MSVC 19.37, x64)에서 실제로 빌드·실행해 247/247(100%) 통과를 확인했다.

## 산출물

- `platform/CMakeLists.txt`, `platform/tests/CMakeLists.txt` — `PLATFORM_BUILD_TESTS` 옵션(기본 OFF)으로 상위 프로젝트에 영향 없이 platform 자체 검증 가능.
- `platform/tests/` 42개 `.cpp` (소스 폴더 구조 미러링) + `platform/tests/fixtures/model_import/` 픽스처.
- `platform/docs/dependency/googletest_20260811.md` — WOT 선행 평가를 인용하고 platform 관점 Wrapper Design(빌드 타겟 경계 격리)을 재정리, Step 3 전체 `[x] Verified`.
- `platform/docs/testing_방법_단위테스트_도입_20260811.md` — 빌드/실행 방법과 신규 기능 추가 시 테스트 작성 규칙.
- `platform/docs/review/단위테스트_도입_20260811_2320.md` — Code Review(Stage 1+2) + Refactor Inspection 결과, 발견된 항목 전부 `[RESOLVED]`.

## 현재 상태에서 확인된 이슈

없음. platform은 WOT/graphics 등 상위(소비) 프로젝트를 전혀 모른다는 전제로 독립적으로 존재하는 라이브러리이므로(2026-08-11 Q&A, 브레인스토밍·전략 문서 참고), WOT 쪽 재빌드 확인은 애초에 platform의 완료 기준에 포함되지 않는다 — platform 자체 검증(단독 빌드 + 247/247 통과)이 완료 기준의 전부다.

## 스코프 밖으로 남겨둔 항목 (이번 사이클 결정)

- `SqliteDataStore`는 항상 `std::logic_error`를 던지는 스텁 — 실제 SQLite 연동은 별도 dependency_eval + task delegation 필요(이번 사이클 범위 아님, 기존 결정과 동일).
- WOT의 `CMakeLists.txt`가 platform 소스 목록을 여전히 하드코딩하는 구조를 `add_subdirectory` 방식으로 바꾸는 것은 WOT 프로젝트의 별도 작업(브레인스토밍 Q&A에서 명시적으로 범위 제외).
- 테스트 헬퍼/픽스처 클래스의 주석 규칙(Author/Description/Input/Output/Notes/Date)은 이번에 새로 작성한 클래스(`FakeSaveable`, `FakeDataStore`)부터 적용하기로 했고, 기존 이식된 37개 파일에는 소급 적용하지 않았다(Code Review에서 사용자가 결정).
