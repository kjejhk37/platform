# 단위테스트_도입 — Strategy

## 목적

브레인스토밍에서 확정된 결과(전 10개 영역, 동일 깊이, Google Test, 자체 검증 원칙, 별도 테스트 방법 문서)를 실제 코드 변경 단위로 쪼개고, 완료 여부를 체크리스트로 추적한다.

## 구현 전 확인된 사실 (설계에 영향을 주는 발견)

- platform은 현재 자체 `CMakeLists.txt`가 전혀 없다. `World-of-Tank-imitation-Refactoring/CMakeLists.txt`가 `platform_lib` 타겟의 소스 목록을 직접 하드코딩해서 컴파일하는 구조이며, `add_subdirectory`로 platform의 CMakeLists.txt를 참조하지 않는다.
  → platform은 WOT를 모른다는 전제로 완전히 독립적으로 개발한다(확정, 2026-08-11 Q&A). platform 최상위에 신설하는 `CMakeLists.txt`는 platform 자체 검증용일 뿐이며, WOT 쪽 소스 목록과의 동기화·중복 여부는 platform이 신경 쓸 대상이 아니다 — WOT이 필요하면 WOT 쪽에서 알아서 가져간다.
- `engine/`(`IFrameDataPublisher.h`, `DoubleBufferPublisher.h`)은 헤더 전용이며 WOT의 현재 컴파일 목록에 포함되어 있지 않다 — 실제로 아직 아무 곳에서도 사용되지 않는 상태로 보인다. "10개 영역 전체, 동일 깊이" 원칙에 따라 범위에 포함하되, 헤더 전용이므로 테스트는 `#include`만으로 컴파일 가능한 형태로 작성한다.
- `math/`, `geometry/`의 일부 타입(`Vec2`, `Vec3`, `Quaternion`, `Transform`, `AABB`, `OBB`, `Sphere`, `Capsule`, `Cylinder`, `Mesh`)도 헤더 전용이다 — `.cpp`가 있는 클래스(`Matrix4x4`, `Geometry`, `Intersections`)와 동일하게 전부 테스트 대상에 포함한다.

## 구현 체크리스트

### Phase 0 — 테스트 빌드 인프라 신설

- [x] `platform/CMakeLists.txt` 신설 — `platform_lib` STATIC 타겟 정의(WOT의 현재 소스 목록을 기준으로 미러링)
- [x] `platform/tests/CMakeLists.txt` 신설
- [x] `PLATFORM_BUILD_TESTS` 옵션 플래그 추가 (기본값 `OFF`)
- [x] GoogleTest `FetchContent` 연동 (버전 1.17.0, `docs/dependency/googletest_20260811.md` 기준)
- [x] `platform_tests` 실행 타겟 신설 — `platform_lib` + `gtest_main`만 링크, `platform_lib`은 gtest 무의존 확인
- [x] `enable_testing()` + `gtest_discover_tests`로 CTest 연동
- [x] 소스 폴더 구조를 미러링한 `tests/` 하위 디렉토리 생성 (`tests/math/`, `tests/geometry/`, `tests/collision/{bvh,conservative_advancement,fcl,gjk_epa,kdtree,mpr,octree,rtree,spatial_hash,sweep_and_prune}/`, `tests/entity_component/`, `tests/logging/`, `tests/model_import/`, `tests/persistence/`, `tests/serialization/`, `tests/engine/`, `tests/` 루트(Win32Window))
- [x] platform 단독 빌드(상위 프로젝트 없이) + `PLATFORM_BUILD_TESTS=ON`으로 `platform_tests` 정상 빌드/실행 확인
- [x] `PLATFORM_BUILD_TESTS=OFF`(기본값) 상태에서 platform 자체 빌드 확인 — platform 단독 `PLATFORM_BUILD_TESTS=OFF`(기본값) 빌드를 실제로 실행해 `platform_lib.lib`만 빌드되고 `_deps/`에 `googletest-*`가 전혀 받아지지 않음을 확인(별도 `build_off/` 디렉터리에서 검증). platform은 WOT/graphics 등 상위 프로젝트를 모른다는 전제이므로 WOT 쪽 빌드 확인은 완료 기준에 포함하지 않는다 — WOT의 `CMakeLists.txt`가 platform의 신설 `CMakeLists.txt`를 애초에 참조하지 않는 구조(소스 하드코딩)라는 점도 참고로 확인했다.
